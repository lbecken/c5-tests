# THE OBSERVATORY MURDER

An audio-first interactive mystery for the browser. Fully voiced with ElevenLabs.

> During a total solar eclipse, the director of Helios Peak Observatory dies alone
> inside a sealed chamber. Five colleagues, isolated at five stations, each swear
> he was alive when they spoke to him — and no two of them agree about when.
>
> **The clocks disagreed. The shadow did not.**

You are the incident coordinator, two thousand kilometres away, with a radio, an
archive that is erasing itself, and about six hours.

*(This branch of the `c5-tests` scratch repository contains the game and nothing else.)*

---

## Play it

```bash
npm start          # http://localhost:8099
```

No build step, no bundler, no network calls at runtime — it is a static folder.
**Headphones recommended:** the central clue is a sound, not a sentence.

## The design, in one paragraph

Everything on the mountain that can record a time has been corrupted by one
person. Station clocks carry an undeclared correction. The emergency voice relay
buffers eleven seconds. The victim's own cardiac monitor is replaying a loop. Four
of his last five transmissions were recorded the night before, and the fifth was
generated by a voice model. The only witnesses left are the moon's shadow, which
crossed the ridge exactly when three-hundred-year-old orbital mechanics said it
would, and a spacecraft four hundred kilometres up that logged what the mountain
actually radiated. The player's job is to work out which clock to believe.

**Full design documents:** [`docs/BIBLE.md`](docs/BIBLE.md) (characters, murder
method, fair-play audit, and the eleven changes made to the source outline) and
[`docs/CHRONOLOGY.md`](docs/CHRONOLOGY.md) (the true minute-by-minute timeline
against what each witness believes).

### Three things worth knowing about the audio

**1. Room tone is evidence.** Every voice clip is a recording *plus* a looping
room tone, mixed audibly underneath and separable at runtime. Coll's genuine
transmissions carry chamber ventilation **and a tracking-drive whine**. The four
prerecorded fragments carry chamber ventilation and **no whine** — they were
recorded the night before with the dome parked. The fabricated line carries the
**annex**: a laptop fan eighteen inches from a microphone. The archive's
**ISOLATE BACKGROUND** control mutes the voice and lifts the room, turning every
clip into a test. The archive deliberately does *not* print which room a clip
came from until you have earned it.

**2. The rehearsal fragments are literally the same files.** A cue can declare
`reuse` of another cue's voice take, so the "live" replies attributed to a dead
man and the rehearsal recording they were lifted from are the same recording on
disk, processed through different channel filters. The claim the mystery makes
about those clips is true of the artifact.

**3. Some clues can't be modelled, so they're synthesised.** The looped cardiac
telemetry has to be *sample-identical* across two windows — that is the entire
proof of the true time of death, and no generative model can promise it.
[`tools/synth_clues.py`](tools/synth_clues.py) builds it deterministically from
stdlib Python: an irregular fibrillation pattern from a fixed seed, then the same
buffer concatenated with itself. Likewise the infusion rig's double-click, which
must land at exactly 3.6 s into the victim's final transmission.

## Repository layout

```
data/            the script, split by act — the single source of truth
  00-core.json     cast, voice casting, room tones, effect chains, evidence
  10..50-*.json    Acts I–V
  60-interactive   the four puzzles and the final deduction
docs/            narrative bible, chronology, screenshots
tools/
  build.mjs        merges data/ → web/script.json, validates the scene graph
  generate.mjs     ElevenLabs → web/audio/, content-hashed and resumable
  synth_clues.py   the clues that must be sample-exact
  playtest.mjs     headless playthroughs: runtime, endings, case strength
  assetcheck.mjs   every referenced asset exists, serves, and is non-trivial
  uitest.mjs       drives a real playthrough in Chromium
  serve.mjs        static server
web/             the game — plain HTML, CSS and JS, no dependencies
```

## Regenerating the audio

```bash
export ELEVENLABS_API_KEY=...
npm run audio:dry     # cost estimate, generates nothing
npm run audio         # generate; skips anything already cached
npm run audio -- --only=cues --match=c05    # narrow it down
```

Generation is keyed by a content hash of the request, so re-running only
regenerates what actually changed and an interrupted run resumes for free. The
full script costs about **51,000 characters**.

**Voice casting** lives in `data/00-core.json`. Two production notes worth
keeping if you edit the script:

- `eleven_v3` is the better performer but returns near-silence for very short
  text, and several plot-critical lines are two words long. Anything under 120
  characters is voiced with `eleven_multilingual_v2`, which is dependable at that
  length. Multi-speaker scenes use `/v1/text-to-dialogue` on v3 for interruption
  and pacing.
- The fabricated line is generated at **maximum stability** — flatter, more
  uniform, fewer human irregularities. Its tell is a real property of how it was
  made, not a description of one.

## Tests

```bash
npm test          # scene graph + playthroughs + assets
npm run uitest    # full playthrough in a real browser
```

`build.mjs` fails on unreachable scenes, dead ends, dangling references, or key
evidence that can never be obtained. `playtest.mjs` walks four playstyles and
asserts all three endings stay reachable. `uitest.mjs` plays the whole game in
Chromium and fails on any console error or failed request. All three run in CI
before the site deploys.
